# Synthetic data

All CSV files are **synthetic**. They describe simulated students, not real people. They were generated by `r/make_synthetic_data.R` with fixed seeds, and running that script recreates them exactly. Columns: `student_id`, `tutoring` (`yes`/`no`), `score` (0-100).

| File | Notebook example | Simulated with | Planted problems |
|---|---|---|---|
| `tutoring_scores_clean_synthetic.csv` | 1 (and 5–7) | 40 vs 40 students; true means 76 vs 71, SD 10 vs 8 | none |
| `tutoring_scores_no_difference_synthetic.csv` | 2 | 40 vs 40 students; equal true means (72), SD 9 | none |
| `tutoring_scores_unequal_variance_synthetic.csv` | 3 | 30 vs 50 students; true means 78 vs 72, SD 5 vs 13 | none |
| `tutoring_scores_messy_synthetic.csv` | 4 | as the clean file (different seed) | S001 and S041 missing score; S006 = 850 (entry error for 85); S015 label `"yes "` (trailing space); S065 = 95.8 (unusual but genuine) |

**Seed screening.** The files without planted problems are meant to show the normal path. For each of them, the script draws samples with consecutive seeds until no score falls outside the boxplot whiskers, and prints the seed it used. The test result (p-value) is never looked at when a seed is chosen, and no file was tuned to match the numbers in the case-study PDF. All results in the notebook are computed by R from these files when the notebook runs.

On the messy file, R also flags S049 and S052 with the boxplot rule. They were not planted; they come from the random draw, and the workflow asks the user to verify them like any other flag.
