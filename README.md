# Agentic Statistical Analysis Assistant

A course-scale Python statistical assistant with **two distinct LLMs**, **17 LangGraph nodes**
and **NumPy/SciPy statistical tools**. Model A plans and explains; Model B reviews against
original evidence. The user resolves data issues before inference. Local Ollama models can
run without a paid API or model training.

The current layout follows the teammate's
[repository at `b7eff1c`](https://github.com/Junliang-Lyu/statistical-analysis-assistant/tree/b7eff1c4a8035f196ac4bfc73ef3fe88956dadb5):
`stat_assistant/`, `workflow.py`, `tools.py`, `demo.py`, `demo.ipynb`, `build_notebook.py`,
`examples/`, `artifacts/`, `requirements-lock.txt` and the dated assignment folder use the
same names. See [project structure](docs/PROJECT_STRUCTURE.md) for the complete mapping and
[team alignment](docs/TEAM_ALIGNMENT.md) for retained implementation differences.
The local browser interface now follows the same `ui_server.py` and `ui/` convention,
with an adapter for this project's own workflow. The teammate's frozen evaluation inputs
are now adapted to our workflow; date filtering still requires a new CSV.

## Run on Windows

From the project folder:

```powershell
py -m venv "$env:USERPROFILE\.venvs\langgraph-viz"
& "$env:USERPROFILE\.venvs\langgraph-viz\Scripts\python.exe" -m pip install -r requirements.txt
& "$env:USERPROFILE\.venvs\langgraph-viz\Scripts\python.exe" demo.py --mode mock
```

Reuse an existing project environment when available. `requirements.txt` includes
`requirements-lock.txt`, which contains the exact pinned course runtime. Python 3.13 is
the configured CI version. Copy `.env.example` to `.env` only if `.env` does not already
exist; keep keys local.

### Try the browser interface

Start the local server from the project folder, then open
[http://127.0.0.1:8765](http://127.0.0.1:8765):

```powershell
& "$env:USERPROFILE\.venvs\langgraph-viz\Scripts\python.exe" ui_server.py --port 8765
```

The server uses Python's standard-library HTTP server and listens on `127.0.0.1`.
Choose a built-in synthetic case to inspect its CSV preview, research question and
study/variable metadata. Start with **mock** mode for a quick workflow demonstration:
the agents are rule-based, while the graph and Python statistical calculations run.
Choose **real** mode to use the two configured, distinct LLMs; the local defaults are
Ollama `qwen3:8b` and `gemma3:12b`. Real calls can take longer and require the configured
models to be available. A failed real call is reported, without a mock substitution.

For your own CSV, review the study and variable metadata JSON explicitly before
running the analysis. A CSV alone cannot establish independence or randomization.
When the graph pauses on a data issue, choose a permitted correction, exclusion,
verification or stop action. **Source or reason is optional** for correction,
exclusion and verification; a correction still requires a valid replacement value.
The UI submits your explicit choices to the existing workflow; it does not generate
answers or reasons for you or silently remove rows. The original CSV is retained,
and audit records capture the action, affected cell or record, old/new values and
any note you provide. An omitted note is stored as an empty string and displayed
as "No note provided" in the UI. After a delivered report, try re-explanation or a
new confidence level.
Automatic date/subset filtering is unsupported; provide a new CSV for a subset.

The browser polls submitted analysis jobs and displays their status. Session memory
lasts for this server process; restarting clears it. Uploads and local session files
are saved under ignored `artifacts/runtime/ui/`, with correction versions and audit
files under the workflow's ignored runtime directory. This is a local prototype,
without a hosted deployment or persistent multi-user service. Use Ctrl+C in the
server terminal to stop it.

The CLI supports `--mode mock|real`; `--live` is an alias for real mode. An external
CSV requires both `--csv` and `--design-json`, where the latter names a JSON file containing
confirmed design and variable meanings. Supply its question with `--question` and use
`--interactive` to answer data clarification requests in the terminal. Independence and
study design are not inferred from CSV values. For example, after configuring two real models:

```powershell
& "$env:USERPROFILE\.venvs\langgraph-viz\Scripts\python.exe" demo.py --live
```

The CLI selects mock by default; `--mode` or `--live` selects it explicitly. Notebook
and package mode settings are defined in `.env.example`:

- `LLM_MODE=mock`: named rule-based stand-ins; statistical calculations and LangGraph execution remain real.
- `LLM_MODE=real`: actual Model A and Model B. Defaults are `ollama:qwen3:8b` and `ollama:gemma3:12b`; start Ollama and install those models if needed.
- `LLM_MODE=auto`: choose real when the configured setup is available, otherwise mock. The notebook displays the selected mode; it never silently substitutes a mock after a real call fails.

Model names, endpoint, context size, output token cap and timeout are configurable.
Identical provider/model names, default-tag aliases and identical Ollama weight digests
are rejected for the A/B pair. Cloud provider adapters have not been validated with live
cloud calls in this project. Google support needs its optional provider package.

```powershell
& "$env:USERPROFILE\.venvs\langgraph-viz\Scripts\python.exe" -m jupyter lab demo.ipynb
# Offline tests with project-local temporary files.
& "$env:USERPROFILE\.venvs\langgraph-viz\Scripts\python.exe" -m pytest -q --basetemp=artifacts/pytest
# Execute and save the project notebook, choosing the mode explicitly.
& "$env:USERPROFILE\.venvs\langgraph-viz\Scripts\python.exe" scripts/run_notebook.py --mode mock
# Execute the standalone submission notebook.
& "$env:USERPROFILE\.venvs\langgraph-viz\Scripts\python.exe" scripts/run_notebook.py --mode mock --submission
```

The runner also accepts `--output` for a separate executed copy and `--mode real` for an
intentional live rerun. Use **Restart Kernel and Run All** for a fresh interactive run;
the examples use fixed thread IDs. PNG generation requires network access to the Mermaid
renderer. The messy-data example remains paused in headless mode. Set `INTERACTIVE = True`
in its cell to enter your own verified answers in Jupyter.

`python build_notebook.py` regenerates the canonical teaching and assignment notebooks
and clears their saved outputs; execute them again after rebuilding. The assignment
notebook embeds the source and data and can be executed independently of the package
folder. Its current artifact instructions are in
[assignments/2026-10-12/README.md](assignments/2026-10-12/README.md).

New temporary files, statistical request/result logs and execution state are written to
ignored `artifacts/runtime/`. Historical v1 runtime files remain in ignored `outputs/`.
The preserved live evidence in `artifacts/verification/` is separate from the fresh mock
outputs saved in the canonical notebooks. Renaming and reorganizing did not require a new
real-model evaluation. See the verification record for measured results.

## What the assistant does

1. **Plan:** map the question to variable roles, estimand and hypotheses. Supported methods are two-sided Welch t, Pearson correlation, chi-square independence and simple OLS with an intercept.
2. **Diagnose in parallel:** Model A checks semantics/design/goal alignment from a shared descriptive summary; Python checks raw values and method-specific computability. The branches join before routing.
3. **Clarify if needed:** missing scores, invalid labels, impossible values or unusual observations are shown to the user. Each correction/exclusion/verification needs an explicit permitted action; source or reason is optional. Corrections require valid replacement values. The original file stays unchanged, approved changes produce a new data version, and the audit records actions and any supplied notes without inventing reasons. The system never fills in missing values or drops rows silently.
4. **Compute and explain:** Python produces the numerical result. Model A writes a placeholder-based explanation. A program checks required values, common field bindings and decision consistency; Model B checks the rendered meaning against original evidence. One report revision is allowed, then delivery or an issue notice.
5. **Follow up:** a changed confidence level reruns statistics; re-explanation reuses validated numbers; a new question replans and rechecks. A changed file cannot reuse stale diagnostics. Metadata-only changes keep the correction history. Memory currently lasts only for the running graph process.

At most one plan revision, one report revision, two answered clarification rounds and fifteen
model calls per request are permitted. Invalid clarification input is re-asked without changing
data. A tool/model exception is recorded and routed to an issue notice. These limits are policy
settings, not statistical validity guarantees.

The method is chosen from the question and data roles, not from whether its p-value is
significant. Welch does not assume equal variances. Normality diagnostics are descriptive,
not a switch to a rank test. A sparse contingency table stops because an exact-test fallback
is outside this stage. Correlations and observational group differences do not establish
causation. A new confidence level does not change alpha (fixed at 0.05).

## Scope and evaluation

Simple OLS now reports row-linked **Cook's distance**, **leverage**, and the **Koenker
studentized Breusch–Pagan heteroscedasticity test**. Screening thresholds are `4/n` for
Cook's distance and `2p/n` for leverage (`p = 2`, including the intercept). Flags are
descriptive: no automatic deletion or robust standard-error correction is applied.
Warnings become required interpretation limitations. Undefined diagnostics are labelled
unavailable rather than treated as a pass. The browser has two additional regression examples.

Run the evaluation tools from the project root:

```powershell
python benchmark_suite.py --mode offline --resume-fixtures --output my-offline-run
python benchmark_suite.py --mode live --resume-fixtures --output my-live-run
python interpretation_benchmark.py --mode offline --name my-offline-checks
python interpretation_benchmark.py --mode live --name my-live-checks
```

Output directories must be new. Offline mode tests mechanics with declared stand-ins;
live mode calls the configured models. Optional synthetic fixture answers retain the
initial pause and score the continued result separately. Gold labels and numeric
references are withheld from live agents. Human review sheets contain blank ratings;
no model weights are trained. See [benchmark policy](docs/BENCHMARK_V2.md),
[interpretation evaluation](docs/INTERPRETATION_EVALUATION.md) and the verification record
for measured results and unresolved failures.

This is a runnable course prototype, not a general statistical consulting product. It does
not implement automatic filtering, missing-data imputation, paired/clustered models, multiple
regression, arbitrary code generation, causal adjustment or persistent multi-user storage.
For “only last year's data”, supply a new CSV and run a new analysis.

Placeholder checks constrain numeric output, but cannot prove arbitrary prose is correct.
Two different LLMs can still share errors. Keep a separate human-scored benchmark with clean,
ambiguous and failing cases, checking method/estimand alignment, effect and uncertainty,
missingness disclosure, non-significance wording and causal restraint. Human evaluation scores
the whole system; it does not train either model. See the verification record for measured
results rather than assuming these demos establish accuracy.
